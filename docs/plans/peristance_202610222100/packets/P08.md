## Implementation steps

1. Replace each old repository helper with an explicit facade over the matching repository contract. Route every method through the one shared operation scope; do not split or retry atomic calls.
2. Implement createPersistence(provider), composing these facades and lifecycle. Repository facades must call driver.method(input), preserving this for adapters implemented with classes.
3. Return only the existing DTO/result surface and one dispose. Do not expose the provider name, raw driver, pool, query API, transaction handle or per-repository shutdown.
4. Add neutral exports to the root. Redirect its existing createPostgres* exports to their relocated adapter functions temporarily so src/index.ts still compiles. Do not widen this compatibility surface. Record all such forwards and the old pool file for mandatory deletion in P10.
5. Use a synthetic provider with a non-SQL internal representation to prove neutral delegation. It must not import concrete PostgreSQL repositories or emulate pg.query.
6. Test the direct neutral provider/helpers module with a pg-evaluation sentinel. Prepare the corresponding root-index test but activate it only in P10 after legacy exports are removed. Do not claim the root is isolated yet.
7. Keep the intermediate tree typecheckable through the explicitly permitted temporary root forwards. No other compatibility shims or changes to domain behavior are allowed. P09 migrates consumers; P10 removes all legacy exports.
