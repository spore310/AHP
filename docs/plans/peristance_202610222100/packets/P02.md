## Implementation steps

1. Add isPortableText and hasPortableTextTree following C07. Use a neutral constant name for the existing 512-level budget. No adapter import or engine branch is allowed.
2. Characterize ASCII, valid Unicode surrogate pairs, NUL in scalar/value/key, isolated high/low surrogates, nested arrays/objects and the exact depth boundary. Preserve the existing boundary behavior for wire-valid inputs.
3. Keep shape validation, JSON serialization and byte-size checks distinct. The tree predicate checks portable text; it does not certify arbitrary objects are JSON. Avoid unrelated changes to accessors, prototypes, NaN or Date handling.
4. For intermediate build continuity only, keep deprecated old-name aliases in this file until P09 migrates consumers. Mark these as temporary and require their deletion at P09; do not keep them in the final public API.
5. Document NUL rejection as an owned interoperability policy, not a universal JSON requirement. Keep genuine backend encoding/SQL checks in the concrete adapter.
6. Use the tests to prevent a cosmetic rename that changes semantics or an unchecked removal of existing validation.

## Adversarial check

A payload with an escaped NUL in an object key must still fail before reaching persistence. A valid supplementary Unicode character must still pass.
