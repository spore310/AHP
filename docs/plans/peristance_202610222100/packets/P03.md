## Implementation steps

1. Move pg Pool, PoolClient, Queryable, transaction logic, timestamp normalization and SQLSTATE mapping under the PostgreSQL adapter. Keep original pool defaults and parameter semantics.
2. Keep BEGIN/operation/COMMIT/ROLLBACK on one acquired PoolClient. Preserve rollback best effort and unconditional release. A rollback failure must not mask the original operation failure.
3. Retain current RepositoryError translation categories. SQLSTATE numbers are private to this adapter; generic helpers never inspect them.
4. Test pool acquisition failure, operation failure, COMMIT failure, ROLLBACK failure, normal release and result propagation using a driver double. No real network/database access is permitted.
5. Do not add a public withTransaction interface. The adapter-local Queryable may still be pg-derived because it never crosses the portability boundary.
6. Keep the old file available only while existing repositories still import it. Do not create a forwarding shim from neutral pool.ts into the adapter. P08 deletes the legacy copy after callers switch.

## Adversarial check

A transaction helper that uses pool.query after BEGIN can run statements on different clients. The test must distinguish the acquired client from pool.query.
