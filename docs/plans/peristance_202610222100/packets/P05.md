## Implementation steps

1. Move all WorkRepository operations as cohesive units. Retain query parameterization, principalGuard, statement_timestamp, SKIP LOCKED, target filters, attempt rules and conditional settlement.
2. Keep submit inside one transaction: internal ensureSession -> insert -> exact conflict lookup. Duplicate input object keys ordering must not become a JSON.stringify string-comparison bug; preserve PostgreSQL JSONB comparison.
3. Preserve the distinction between a repository replay returning the existing ID and WorkService rejecting failed/cancelled terminal replays. Do not move that service policy into the adapter.
4. Preserve claim/reclaim, renew, complete, fail, cancel, get, exhausted-lease reconciliation and dependent-work checks including terminal rows.
5. Write a query-double that detects use of a different transaction client. Prove same-client session+work calls, rollback on work-insert failure, existing safe result mapping and error categories.
6. Inventory every atomic predicate in a parity table. Do not shorten the SQL, change its clock, introduce retries, or replace it with generic CRUD as part of relocation.
7. Keep SQL text/parameter snapshots or equivalent focused assertions without pretending these exercise database locks. Mark real contention tests as pending authorization.
