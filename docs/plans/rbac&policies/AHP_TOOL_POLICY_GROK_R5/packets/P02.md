## Implementation steps

1. Implement defineToolPolicyNamespace with a name, exact revision, generic readonly policy array, optional includes and registered domain resolver. A standalone direct policy registry works with namespaces: [].

2. Compile using Map/own-key lookups. Validate every reference, capture immutable policy data, retain functions only in private registries, reject cycles/conflicts and bound recursion/counts. De-duplicate equal references deterministically; reject different definitions for the same exact identity.

3. Implement explicit session-type and provider bindings. forSessionType returns admitted policy/namespace references and a separately maintained mandatory set, not grants for every participant.

4. Resolve only registered and admitted references. Treat workspace.review@pm as an opaque ID. A resolver cannot remove a required provider rule or select an unregistered policy. Dynamic evaluator failures deny; invalid static manifests fail at construction.

5. Freeze namespace expansion at assignment/revision boundaries. Later new namespace members must not enter an existing assignment silently. Make the resolution graph inspectable in tests without publishing private functions/conditions to clients.

6. Retain existing tool identity/catalogue machinery. Do not introduce another schema language or auto-import policies by filesystem/package name.
