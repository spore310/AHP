## Implementation steps

1. Register host-owned action factories against exact contract and implementation revisions. Keep execution location/provenance separate from session-provider identity and client advertisements.

2. Resolve caller authority and mandatory provider/resource constraints using the same dispatcher. A trusted executor is not permission for every caller; do not run it under global admin on behalf of an unauthorized agent.

3. Demonstrate using a pure in-memory action such as a bounded echo/summary fixture. No filesystem, shell, model runtime or cloud credentials are necessary.

4. Ensure host and client routes expose equivalent policy/challenge/result semantics while preserving different implementation trust. Never fall back from a denied/missing host executor to an arbitrary client handler.

5. Apply capacity, cancellation/draining, cleanup and result projection rules to host actions. Keep secrets/resources local to trusted adapters and out of descriptors or serialized invocation contexts.
