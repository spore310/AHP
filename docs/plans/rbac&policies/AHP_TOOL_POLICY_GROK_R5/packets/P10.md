## Implementation steps

1. Implement one recipient-aware egress/projection service; keep canonical session state untouched. Remove raw tool lists from protected shared manifests/activeClients/serverTools surfaces and use the private assignment view.

2. Apply identity/resource permission to initialSubscriptions, subscribe/repeated subscribe, root/list/catalogue metadata and all relevant actions/errors. A denied target returns a sanitized absence/denial without echoing hidden definitions.

3. Filter listing rows before counts and pagination; bind cursors to view/scope revision. Prevent resource existence leakage via global root active count or provider catalogue where policy hides it.

4. Queue authorized-view intents or bounded records, not irrevocably preapproved raw frames. Reauthorize/reproject after awaits and immediately before send; revoke drops payloads and closes/invalidate affected views.

5. Project native session active-client actions consistently with projected snapshots (empty structured tool lists in protected shared fields). Do not reveal raw advertiser descriptors through a special broadcast acknowledgement.

6. Exercise the actual pinned SDK reducer: allowed snapshot plus projected actions must equal the next projected state. Keep serverSeq semantics; use separately named assignment viewRevision for private changes. If an upstream transition cannot represent the safe projection, implement/document a negotiated private resnapshot rather than leaking or inventing native semantics.

7. Inspect the complete P00 egress inventory and attach an explicit check to each path. Sensitive content already transmitted cannot be recalled; raw user text is governed by its resource policy, not universal hidden-name filtering.
