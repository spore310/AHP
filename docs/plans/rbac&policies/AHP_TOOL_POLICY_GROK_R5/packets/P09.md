## Implementation steps

1. Register exact contract/policy/implementation bindings separately from ToolContractDefinition. Keep catalogue validation, bounded inputs/results and canonical descriptors intact.

2. Adapt broker calls to the dispatcher using verified actor, origin/target resources, session instance and current assignment. Subscription is necessary only where the protocol requires it; it never substitutes for permission.

3. Authorize advertisement and execute/receive independently of caller invoke. Run async policy checks before the synchronous reducer, then freshness/connection checks immediately before committing an accepted advertisement.

4. Retain exact chosen executor connection and contract identity correlation. Key executor eligibility by connection/security context, not only clientId or model name. Ambiguous admitted executors deny unless an explicit tested routing policy exists.

5. The host never runs client-supplied lifecycle functions; authorization-relevant normalization is trusted host code before dispatch. Treat results as untrusted data: check sender, selected implementation, generation/instance, output bounds/schema and pending call state. Duplicate or late completion cannot project twice or settle another invocation.

6. Do not broaden the current schema compiler to trust client advertisements. Proposed new contracts are deferred to P16. Do not implement server functions yet; P15 supplies that adapter through the same lifecycle.
