## Implementation steps

1. Define domain-qualified identity, actual user/agent context, resource instance, direct policy/namespace references, admission ceilings, mandatory rules, scoped bindings, issuer bounds and freshness stamps. Preserve the existing principal contract or a deliberate compatibility export.

2. Define typed ports for identity/actor resolution, grant reads/issuance, resource relationships and policy decisions. Use typed input/return objects, Promise support and no HTTP, socket, ORM, model or OS handles in portable contracts.

3. Keep ToolActorPolicy generic over application strings, with runtime role and grant arrays empty by default. Define explicit direct-grant versus role-gated modes so empty anyOf does not become allow-all. No SDK role names are supplied.

4. Define separate tool execution/provenance registration, caller versus executor contexts, action lifecycle and challenge ports. Resolve optional prepare honestly: execute receives prepared or undefined; do not cast to a guaranteed generic resource.

5. Add runtime schemas and finite limits for untrusted/configuration data using existing dependencies. Unknown enum/effect, malformed revisions, prototype-key selectors and invalid discriminated combinations reject. Runtime callback registries are not serialized into manifests.

6. Write compile-time consumption fixtures for two unrelated application role vocabularies and custom extensions. Ensure a generic policy array remains assignable without using any or Record<string, never> traps. Public indexes export; helpers implement. Map every new source file immediately in README.
