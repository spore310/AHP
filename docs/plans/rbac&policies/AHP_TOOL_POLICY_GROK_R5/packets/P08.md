## Implementation steps

1. Implement ToolAction and the SDK-owned dispatcher as composed typed helpers. Resolve trusted upstream context, bound/validate raw input and perform coarse resource access before costly hooks.

2. Run optional authenticate(context,input) as additional app validation only. Run validate returning void or typed normalized-input result. Recheck normalized input schema and all resulting target resources; there is no separate validated argument in prepare.

3. Evaluate current grant path and mandatory rules before preparation. A required challenge without a configured handler fails closed for now; no pass-through placeholder. Reserve continuation types for P13.

4. Use per-invocation action factories by default. prepare receives canonical input, immutable context/AbortSignal and onCleanup; generic preparation may return a callback or local handle. execute receives optional prepared state honestly.

5. Attempt action cleanup followed by all registered LIFO callbacks exactly once after settlement, including partial prepare and output-validation failures. Preserve primary errors and separately sanitize cleanup diagnostics.

6. Separate client-facing timeout/cancel from actual action settlement. Abort is cooperative; retain draining ownership and capacity while an action still uses its resources. No reexecution, automatic retry or claim that cancellation undoes effects. Host stop fences late callbacks, drains safely and does not lose cleanup ownership.

7. Validate outputs before accepting result; do not publish arbitrary result actions. Enforce finite in-flight/retained-result bounds and sanitized error codes with injected clocks for tests.

| ID | Requirement | What distinguishes a correct implementation |
| --- | --- | --- |
| L01 | Typed hooks never see unbounded unvalidated data | Oversized/schema-invalid input rejects before custom action hooks. |
| L02 | Auth hook cannot bypass initial authority | Successful optional hook does not grant a denied actor; missing hook does not skip SDK checks. |
| L03 | Normalization cannot redirect after authorization | Changed path/resource gets schema and policy rechecked; frozen canonical input is used downstream. |
| L04 | Generic preparation is local and optional | Void/no prepare and custom callback/handle preparation work without framework or unsafe non-null casts. |
| L05 | All cleanup is attempted once | Partial prepare, execution failure, output failure and cleanup failure exercise correct LIFO/primary-error behavior. |
| L06 | Timeout does not release live resources | Park action after abort; track draining/capacity and delay cleanup until safe settlement. |
| L07 | No shared action state across users | Concurrent calls use separate action instances/prepared resources; no cross-request mutation. |
| L08 | Errors and outcomes preserve uncertainty | Secret-bearing thrown errors are sanitized; post-effect cleanup failure does not trigger automatic retry. |
