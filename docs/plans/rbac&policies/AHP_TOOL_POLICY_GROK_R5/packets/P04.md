## Implementation steps

1. Add host-level security configuration independent of agentWork and a DB URL. Bridge the existing authenticator through one explicitly chosen source. If old/new authenticators conflict, reject configuration; do not silently choose whichever permits access.

2. Resolve identity and initial direct policy grants before protected initialization/subscription data leaves. Keep the current frame hold during asynchronous authentication; add finite setup time/size bounds and failure containment.

3. Distinguish successful native protocol setup from authorization to protected resources. No configured authority means no protected tool assignment. A trusted-local profile is explicit and bounded, not a synthetic admin/user fallback.

4. Resolve actor class from trusted application context. An absent agent presence binding never proves the caller is human. Agent classification requiring registration remains pending/denied for protected tool calls until the binding is verified.

5. Keep connection identity immutable during one context generation. Credential/grant rebinding fences stale admissions. Verify any user-on-behalf-of relationship through the application port, not a JSON field from the tool call.

6. Retain existing durable agent/work injection and its ownership semantics. Do not modify registration rows, database adapters or role columns. Validate multiple-domain/legacy-subject compatibility at composition as specified in A8.
