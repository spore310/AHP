## Implementation steps

1. Implement application-injected begin/verify and optional cancel/status. Store only bounded private invocation state and opaque IDs; validate safe wait/redirect presentation metadata against host policy.

2. When any mandatory policy requires a challenge, return challenge-required before prepare. No configured verifier means denial. No unbounded original JSON-RPC request or generic priority bypass.

3. Bind continuation to actual actor/delegation, connection/rebind policy, resource and session instances, exact contract/executor registration, canonical input, obligations, policy/grant/auth revisions and expiry. Input is server-stored; resume cannot replace it.

4. Verify via trusted callback/adapter, distinguish MFA from human approval of an agent action, and atomically consume once. Concurrent valid resumes admit at most one execution. Reauthorize all current requirements before preparation; changed executor/input/resource requires a new approved call.

5. Expire/cancel on disconnect, session destruction, policy changes or restart according to explicit in-memory semantics. Bound per-actor/global pending counts, proof/metadata bytes and verification time. Late callbacks cannot reopen a consumed/expired record.

6. Test unknown/denied status and stale proof without revealing another actor state. Keep the implementation technology-neutral; no specific IdP, cookie, TOTP, passkey or browser UI is installed.

## Required test coverage

| ID | Requirement | What distinguishes a correct implementation |
| --- | --- | --- |
| C01 | Required challenge cannot be skipped | No verifier, false proof or client mfaPassed flag produces zero prepare/execute calls. |
| C02 | Continuation is nonblocking | Same-socket challenge/status/resume succeeds without holding the first dispatch. |
| C03 | Exact request binding enforced | Input, actor, resource instance, policy revision or selected executor substitution invalidates approval. |
| C04 | Continuation is atomic single use | Two simultaneous valid resumes result in one admitted execution; duplicate completion cannot project twice. |
| C05 | Current revocation still wins | Grant revoked during verify causes denial; replay/expiry/disconnect/restart cannot resurrect authority. |
| C06 | MFA is not delegation or human consent | Agent remains agent; satisfied identity step-up alone does not authorize a separate approval obligation. |
| C07 | Challenge metadata and storage are bounded | Unapproved redirects, secret metadata, excessive pending/proof bytes and hanging verifier fail safely. |
