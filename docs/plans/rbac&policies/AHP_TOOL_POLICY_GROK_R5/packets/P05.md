## Implementation steps

1. Add exact policy admission, mandatory refs and optional creator-bootstrap template to session application/type registration. No built-in role or unconditional owner-admin assignment. Keep the existing tool catalogue ceiling separate.

2. Replace SessionApplicationOptions.role as a protected authorization source. Reject conflicting legacy authority options or make them explicitly inert/deprecated; do not run old role filtering alongside new per-actor grants.

3. Authorize session creation, selected type/provider and approved bootstrap before any usable record exists. Resolve async policy callbacks outside the current synchronous onRecordCreated hook.

4. Mint a resource instance ID. With a current decision stamp, synchronously attach the record, owner fact and local bootstrap bindings before catalogue publication/backend startup. Roll back the newly attached instance and bindings if the installation fails.

5. Provide the old work owner interface as a projection of the canonical owner fact. Role changes never rewrite ownership. Non-owner participants keep their own subjects; do not substitute the creator identity to authorize them.

6. Fence teardown and late backend completion by expected instance, not just URI or subject. Same-URI recreation cannot inherit old grants/challenges and stale disposal cannot remove the successor owner.
