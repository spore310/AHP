## Implementation steps

1. Add propose/approve/publish operation authorization independently from invoke/advertise. A candidate proposal is not an allowed catalogue entry. Use authenticated actor context and exact scope.

2. Apply existing definition size/depth/schema-subset limits before accepting/compiling untrusted proposals. Bound pending proposals and compilation admission; do not enable remote schema loading, arbitrary evaluation or executable code uploads.

3. Approved update produces immutable exact contract/origin registration. Prevent replacing an existing trusted revision under the same identity. Use a narrow revisioned runtime registration overlay/service rather than making all existing catalogue reads mutable.

4. Require explicit approval authority; self-approval is not implied by publisher permission. Permit a consuming app to explicitly configure it only through a separate trusted rule. Publication does not change runtime trust of client-owned code.

5. Updating available catalogue does not silently assign tools to live sessions. Require separately authorized assignment/manifest revision and invalidate views. Existing advertisement still validates exact canonical schemas and separate executor eligibility.

6. Keep runtime code distribution out of proposal JSON. P17 defines an approved artifact seam, not arbitrary client function transfer.
