## Implementation steps

1. Define an artifact descriptor pinned to approved publisher, contract, implementation revision, runtime/platform and expected digest with trusted verification metadata. Keep archive/package format opaque to the SDK.

2. Provide artifact source/verifier and explicit client runtime-loader interfaces. The reference implementation uses inert in-memory fixture bytes and a known test handler, not downloaded code or eval.

3. Authorize metadata/locator/byte delivery by purpose-specific assignment and resource policy. Bound byte counts/chunks/TTL. Validate source locators in the host adapter; no client-controlled SSRF-style arbitrary URL fetch is added.

4. Verify exact bytes before handing them to a loader and bind subsequent executor registration to the approved revision. Changing the bytes, contract or runtime invalidates verification; untrusted self-reported hash is insufficient.

5. Require the consuming client runtime to explicitly accept loading/execution and enforce its own sandbox/resource policy. The SDK refuses when no loader exists. No installer, dependency manager, OS isolation or remote attestation is promised.

6. A locally loaded handler still enters the normal client executor path; no artifact-specific shortcut around invoke/execute permissions, challenge or result validation.
