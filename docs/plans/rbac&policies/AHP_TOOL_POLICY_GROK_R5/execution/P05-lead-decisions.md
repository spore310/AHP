# P05 planning decisions — no implementation authorization

P04 is still being implemented. Use this with Luna's `P05-preflight.md` when preparing the bounded P05 plan after P04 acceptance. No P05 source writes or P03 API amendments are authorized by this note.

1. **Creation is an explicit application capability, not a tool invoke grant.** Prefer a session-owned, type/provider-specific trusted creation/bootstrap preparation callback. Do not extend P03 ToolOperation merely to make creation look like invocation, or invoke the P06 general issuer prematurely. The exact registered type declaration captures admission/mandatory refs plus an optional finite creator template. The callback must explicitly approve both creation and that template for the actual trusted actor, selected type/provider and freshly minted candidate instance. Its bounded result supplies expiry, synchronous currentness and release; no client roles/owner/bootstrap authority enters it. Missing policy/approval denies. The SDK validates any resulting grant against the captured template and admission; an approval is not permission to invent arbitrary policies/roles/other recipients. Final signatures await the P05 plan review.

2. **Failed backend remains inspectable, but bootstrap does not remain usable.** Preserve the established failed-session record and immutable canonical owner fact. Withdraw the exact newly installed bootstrap grants on startup failure before exposing the failure event, and invalidate their decisions/assignments. Do not erase and silently reconstruct ownership, create an owner cache, or leave an ownerless visible record. The current P03 trusted registry lacks narrow removal; P05 should propose a minimal expected-instance/expected-revision conditional binding-removal primitive, reusable by P06, with atomic no-op on stale/missing input and positive/negative regression controls. This would be an explicitly reviewed P03 amendment, not implicit permission to edit accepted code. General delegation/lineage issuance remains P06. Future participant issuance must not target an unavailable/failed session.

3. **Reserve before await; cancel without waiting indefinitely.** Factory-owned finite URI reservations precede asynchronous preparation and are invisible as live records. Host/factory stop and applicable disposal cancel the reservation synchronously. Late prepared results are released once, never attached. Final attach validates the captured reservation, instance and live trusted connection/currentness with no intervening await; failure rolls back only this candidate instance. Preserve existing backend record-object fencing.

4. **One canonical owner plus separate lifecycle state.** The P03 resource owner's full domain-qualified subject remains authoritative. Work consumes a read-only projection over the current attached resource and configured single work domain; retain existing subject equality and lease logic unchanged. A separate finite exact-instance settle marker may retain URI lifecycle exclusion during disposal, but must not become another writable owner store. Standalone legacy owner registries remain for old internal tests. Explicit protected composition rejects conflicting owner sources.

5. **Capture type authority immutably and keep it out of wire metadata.** Runtime callbacks/templates belong to trusted registration, not the serializable session definition/snapshot. Protected creation cannot use the legacy global role as authority; reject explicit conflicting role configuration or make legacy fields explicitly inert under the new path. Keep tool catalogue bounds separate from policy grants. The P05 plan must identify exact type/export/owner-lookup additions and affected existing fixtures before execution.

All S01–S05 controls in the preflight remain required, including partial-binding rollback, canonical owner retained without failed bootstrap, independent participant subjects, stop/duplicate-create races, and stale cleanup versus a same-URI successor. Do not reopen P04's no-raw-egress boundary: enabling protected creation in P05 does not authorize returning raw snapshots or tool lists before P10.
