## Findings

### F1 — P2, open (blocking): a stale, self-disposed create late-binds onto a concurrently-created foreign live record; the true creator is locked out and the stale principal gains the durable work channel for that live session

**Evidence (code trace + reproduced rig).** The create handler binds after the factory resolves (`src/websocket/helpers/ahp/helpers.ts:371–401`; bind at 393–399). `executeCreateSession` inserts the registry record synchronously, then awaits the backend start (`src/sessions/createSession/helpers.ts:95,101`); when the record is removed mid-start, the factory resolves the create successfully after releasing the late backend (`src/sessions/createSession/helpers.ts:169–185` — the early `return` still resolves the promise), and the handler then runs `options?.sessionOwners?.bind(uri, subject)` unconditionally. `createSessionOwnerRegistry.bind` only conflicts on a *cross-subject incumbent* (`src/work/helpers/helpers.ts:158–164`); it cannot know whether the caller's create still owns a record. The binding-level pre-check (`ahp/helpers.ts:378–391`) reads `owner()` once before the create and is blind to a binding that lands afterwards. The round-2 all-principals window probe conditions only on `owner !== undefined && snapshot === undefined` — it cannot see this shape, because here the snapshot **exists**.

Rig (real `createSessionsFactory` + `createAHPBinding` + real registry + real `createWorkService`, provider start parked, everything released on demand):

1. alice creates URI `U` (record live, backend parked, no binding yet — bind happens only at create resolution);
2. alice disposes `U` — record deleted synchronously (`src/sessions/helpers/factory/helpers.ts:203`), back-endless record returns immediately (209–211), `finally` unbind is a no-op (ahp/helpers.ts:416–423), dispose replies success;
3. bob creates the same URI (pre-check passes: owner undefined), record live, backend parked;
4. alice's parked start resolves → late-backend detection releases her backend (createSession/helpers.ts:171–185) → her create resolves as **success** → `bind(U, "alice")` wins;
5. observed: `owner(U) = alice` with bob's record live; alice's durable `submit` onto bob's mid-flight record: **accepted** (durable row recorded — the host projection synthesizes the owner from the registry, `src/websocket/helpers/host/helpers.ts:86–95`, so the service's owner checks pass, `src/work/helpers/helpers.ts:182–196`); bob's create reply: `Conflict` (−32011); bob's `submit`: `unauthorized`; bob cannot dispose (`owner !== principal` deny, ahp/helpers.ts:403–411) and cannot recreate (`SessionAlreadyExists`, createSession/helpers.ts:57–62).

The codebase's own declared invariant — "Creating first would leave the caller with a live record its true owner can neither bind nor dispose" (ahp/helpers.ts:375–377) — now holds in reverse for the true creator. This goes beyond the round-02 documented "Same-owner recreate residual" (`src/work/README.md:109–113`), which is explicitly same-owner and submission-write-scoped; the late-bind takeover is cross-creator and binding-scoped, and no README text mentions it. Service-level checks followed here (`live.ownerPrincipalSubject === registry.owner ===Caller`) never read record identity, because `SessionSnapshot` exposes no stable session-generation field — the same missing-identity root the round-02 triage recorded.

**Reachability:** needs `provider.startSession` latency (any real integration; the mock that ships today starts immediately). That is the same evidentiary premise the accepted round-01 P2 reproduction used (test-gated backend disposal); round 1 and 2 closed dispose-latency races as P2 on that premise, so this is held to the identical standard. The victim URI is fully attacker-chosen — `sessionUriSchema` constrains only scheme + non-empty id (`src/sessions/types.ts:23–28`), and any connection may dispose an ownerless record (see F4).

**Proposed fix (non-frozen modules only).** Give the settle path the record identity it lacks: resolve `SessionsFactory.createSession` with a one-shot creation token (record-identity handle from `src/sessions/` — unfrozen), and let `SessionOwnerRegistry.bind(uri, subject, token)` (or a binding-level token map keyed off the existing `root/sessionAdded`/`root/sessionRemoved` catalogue subscriptions) reject a bind whose token is no longer current — a stale/disposed create then either skips the bind (ghost is never created, fixing F2 too) or surfaces a typed conflict instead of silently claiming the URI. No change to `src/agents/types.ts`, `src/persistence/types.ts`, `src/work/types.ts`.

### F2 — P3, open: a create racing a settle creates a *ghost owner binding* — binding without a live record with no settlement left to release it; round-2 closure removed the old self-heal (owner recreate)

**Evidence (reproduced rig, variant G, final run problems = []).** Same late-bind root as F1, weaker impact: fresh URI → create (start parked) → anyone disposes (back-endless record → immediate resolution, `factory/helpers.ts:209–211`) → dispose settles (finally unbind already done) → parked start resolves → create resolves → **bind lands after the settlement**: `owner(U) === "alice"` with `getSessionSnapshot(U) === undefined`. Consequences observed: the round-2 probe now treats this as a settling window, denying recreates to *everyone* including the true owner (`Session not found`, ahp/helpers.ts:385–389) — until the owner issues one extra dispose that *replies with an error* (`SessionsError` SessionNotFound, code −32001, thrown at `factory/helpers.ts:200–202`) but still releases the binding in `finally` — after which the rebind succeeds and its record is live and owned. Also observed: the racing create replies **success (null)** to its caller for a session that no longer exists. No seizable record and no cross-principal work impact (submit requires a live record, `work/helpers.ts:186–188`) — hence P3, but the recovery semantics ("repair by issuing a failing dispose") are undocumented and round-2 removed the recreate-based recovery that previously existed. Restatement of the bug family the round-2 fix targeted ("a create succeeds while a stale binding exists") via the *settlement-last* interleaving rather than the mid-window one.

**Proposed fix:** with F1's token, a create whose record was removed while its backend was starting must not bind at all (and should not reply plain success); alternatively document the extra-dispose recovery in `src/websocket/README.md` beside the disposal paragraphs (lines 158–163) if the token is deferred.

### F3 — P3, open: during the create-in-flight window (record live, binding not yet set) any connection — including an unauthenticated one — can dispose the record

`disposeSession`'s ownership deny only fires when a binding exists (`ahp/helpers.ts:403–411`); the create path binds only after the factory resolves, so the producer of the record has no protection while its backend starts. This is the permissionless lever that arms F1 against a victim, and it weakens the round-01 intent (binding-restricted disposal). Shipped mocks start immediately so the shipped-composition window is microtask-scale, but any real provider widens it; an authenticated attacker with no relationship to the victim can drive all steps. Suggest either binding at the earliest safe point, or documenting the in-flight window explicitly in `src/websocket/README.md`. Non-blocking on its own (baseline POC sessions are documented as host-global, `README.md:150–154`), blocking only as a prelude consideration for the F1 fix.

### F4 — P3, **hypothetical** (labelled separately): a throwing custom `SessionOwnerRegistry.unbind` inside the dispose `finally` would strand a settling window (record gone, binding kept, error superseded)

Presently unreachable: the only shipped registries (`work/helpers.ts:168–173`, the NOOP at `ahp/helpers.ts:92–97`) cannot throw, and a custom registry is injectable only by tests/embedders via `AHPBindingOptions`. If it ever threw, the `finally`'s error would replace the factory's outcome and leave owner-without-record permanently. Trivial hardening: wrap the unbind call per the binding's existing isolation style (cf. `ahp/helpers.ts:527–536`). Filed as hypothetical only.
